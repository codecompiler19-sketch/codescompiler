# Bem CSS

This original CodesCompiler lesson explains **Bem CSS** through practical CSS, clear property references, responsive behavior, and a realistic design use case. The examples are written for CodesCompiler’s interactive learning experience and are not copied from any third-party tutorial.

## What you will learn

You will learn the purpose of this technique, its syntax, the relevant CSS properties, how the browser applies the rule, how to combine it with HTML, and how to test it on a responsive CodesCompiler page. The lesson also covers accessibility, performance, maintainability, and common mistakes.

## Core idea

CSS describes presentation without changing the meaning of the HTML document. A good rule makes the content easier to read, navigate, or understand. Start with semantic HTML, add a predictable class name, and use the smallest set of CSS properties that expresses the design requirement.

> **Tip:** In the CodesCompiler editor, change one declaration at a time. Observe the result, inspect the computed style, then keep the rule only if it improves the design at the target viewport sizes.

## Basic syntax

A CSS rule contains a selector and a declaration block. Each declaration has a property and value separated by a colon and terminated by a semicolon.

```css
.cc-lesson-card {
  color: #152a24;
  background: #ffffff;
  padding: 1.5rem;
  border-radius: 1rem;
}
```

The selector chooses elements. The properties describe the visual result. CSS custom properties, logical properties, relative units, and media queries help a design scale beyond one screen size.

## Properties and values

The most relevant properties for this topic are grouped below. Values should be chosen according to content, layout context, and accessibility needs rather than copied mechanically.

| Property or concept | Purpose | Practical guidance |
| --- | --- | --- |
| `display` | Chooses the element’s layout participation | Use Grid or Flexbox for layout instead of spacing hacks. |
| `color` and `background-color` | Define foreground and surface colors | Check contrast and do not communicate meaning by color alone. |
| `margin` and `padding` | Control outside and inside spacing | Prefer a consistent spacing scale and logical properties when appropriate. |
| `width`, `max-width`, and `min-width` | Constrain sizing | Avoid fixed widths that cause overflow on small screens. |
| `font-size` and `line-height` | Control readable text scale | Use scalable units and comfortable line height. |
| `border`, `border-radius`, and `box-shadow` | Define edges and elevation | Keep decoration subordinate to content and focus states. |
| `transition`, `transform`, and `animation` | Add motion and state changes | Respect `prefers-reduced-motion`. |
| Custom properties | Store reusable design values | Define tokens in `:root` or a component scope. |

### A design-system variation

```css
:root {
  --cc-brand: #087f5b;
  --cc-ink: #152a24;
  --cc-surface: #ffffff;
  --cc-space: 1rem;
  --cc-radius: .75rem;
}

.cc-callout {
  color: var(--cc-ink);
  background: var(--cc-surface);
  padding: var(--cc-space);
  border-inline-start: .35rem solid var(--cc-brand);
  border-radius: var(--cc-radius);
}
```

Tokens make it possible to update a CodesCompiler theme from one place. Keep names meaningful and avoid using custom properties to hide unrelated behavior.

## Advanced and responsive design

Advanced CSS is usually about relationships rather than isolated declarations. The cascade, specificity, inheritance, containing blocks, stacking contexts, formatting contexts, and intrinsic sizing all affect the final result. Prefer low-specificity selectors and component boundaries that are easy to reason about.

Use media queries and container queries when a component must adapt to available space. Use `clamp()` for fluid values, `minmax()` for flexible grid tracks, and logical properties for interfaces that may support different writing directions.

```css
.cc-layout {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: clamp(1rem, 3vw, 2rem);
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: .01ms !important;
  }
}
```

## Accessibility, performance, and SEO

CSS must not remove meaningful content or make keyboard focus invisible. Maintain readable contrast, support zoom, avoid text embedded only in background images, and preserve a logical source order. Use visible `:focus-visible` styles and make touch targets large enough for comfortable interaction.

For performance, avoid unnecessary expensive filters, huge background images, layout shifts, and long chains of overrides. Prefer efficient selectors, compressed assets, and animation of compositor-friendly properties when appropriate. For SEO, remember that CSS supports discoverability indirectly: readable content, clear hierarchy, fast rendering, and mobile usability matter more than decorative effects.

## Common mistakes

- Using fixed pixel sizes everywhere and creating horizontal overflow.
- Solving a layout problem with repeated margins or `<br>` elements.
- Relying on color alone to communicate status.
- Increasing specificity until the stylesheet becomes impossible to maintain.
- Removing focus outlines without replacing them.
- Animating large layout changes without a reduced-motion alternative.
- Using `!important` as the first solution to a cascade problem.
- Hiding content with CSS when it should remain available to assistive technology.

## CSS and JavaScript integration

JavaScript should toggle classes or data attributes rather than rewrite large inline style strings. CSS can then describe each state clearly.

```css
.cc-lesson-panel[hidden] { display: none; }
.cc-lesson-panel[data-state="open"] { display: block; }
```

```html
<button class="cc-toggle" type="button" aria-expanded="false" aria-controls="cc-lesson-panel">
  Show lesson notes
</button>
<section id="cc-lesson-panel" class="cc-lesson-panel" hidden>
  <p>These notes remain part of the document structure when revealed.</p>
</section>
```

## Testing checklist

1. Test the component at narrow, medium, and wide viewport sizes.
2. Use keyboard navigation and verify visible focus.
3. Zoom to at least 200% and check for clipping or overlap.
4. Check text and interactive-control contrast.
5. Test reduced motion if the lesson includes animation or transitions.
6. Inspect computed styles and remove conflicting declarations.
7. Validate HTML and CSS, then test in more than one browser engine.

## Summary

| Takeaway | Why it matters |
| --- | --- |
| Start with semantic HTML | CSS should enhance content rather than replace its meaning. |
| Know the relevant properties | A small, intentional rule set is easier to debug and scale. |
| Design responsively | Components must work across viewport sizes and zoom levels. |
| Respect accessibility | Contrast, focus, motion, source order, and readable type are design requirements. |

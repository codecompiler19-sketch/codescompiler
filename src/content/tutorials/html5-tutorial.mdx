## Core concept

HTML describes document structure and content meaning. Choose a native element or attribute that represents the content accurately. CSS should handle appearance and layout. JavaScript should add behavior without removing the useful semantics already provided by HTML.

> **Tip:** Open the browser accessibility tree and test the example with only a keyboard. A visually correct result can still have incorrect structure.

## Basic example

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>HTML5 tutorial example</title>
  </head>
  <body>
    <main>
      <h1>HTML5 tutorial</h1>
      <p>Write real code, run it instantly, and build your web development skills step by step.</p>
    </main>
  </body>
</html>
```

The doctype enables standards mode. The language, character set, viewport, title, landmark, heading, and paragraph all serve different purposes. Do not use CSS font size as a substitute for choosing the correct element.

## Syntax, attributes, and variations

The most important rule is to match the markup to the content. Keep elements correctly nested, close non-void elements, quote attribute values, and use lowercase names consistently. Use `class` for reusable styling hooks, unique `id` values for document relationships, and `data-*` attributes for private application data.

| Feature | Purpose | Recommended practice |
| --- | --- | --- |
| Native element | Expresses content meaning | Prefer it over a generic `div` with a role. |
| Attribute | Configures an element or relationship | Use documented values and quote strings. |
| `class` | Reusable CSS or JS hook | Use stable, descriptive names. |
| `id` | Unique target or relationship | Never duplicate an ID in a document. |
| `aria-*` | Adds missing accessibility state or relationship | Use only when native HTML is insufficient. |
| CSS | Presentation and layout | Keep visual rules outside the markup. |
| JavaScript | Dynamic behavior | Preserve a usable HTML fallback. |

### Structure and nesting

Elements must be nested completely. An element opened inside another must close before the outer element closes. Invalid overlapping markup makes browser repair unpredictable and may confuse selectors, scripts, and assistive technology.

### Native behavior

Native HTML controls usually provide keyboard support, focus behavior, validation, and accessibility semantics. Replacing a button, link, form control, or disclosure with a clickable `div` creates unnecessary work and often introduces defects.

## Accessibility and SEO

Use a meaningful accessible name for controls and landmarks. Provide alternative text for informative images, captions or transcripts for spoken media, labels for form controls, and a logical heading order. Preserve visible focus indicators and test zoom, small screens, keyboard navigation, and reduced motion preferences where animations are involved.

Search engines can better interpret pages with descriptive titles, useful headings, semantic sections, descriptive links, fast media, and content that genuinely answers the visitor's question. HTML alone does not guarantee rankings, but poor structure can make content harder to understand and use.

## Common mistakes

- Using a generic element when a native semantic element exists.
- Choosing markup for its default appearance instead of its meaning.
- Omitting labels, alternative text, captions, or useful link text.
- Duplicating IDs or creating invalid nesting.
- Using `<br>` for spacing or a table for layout.
- Relying on client-side validation as a security boundary.
- Hiding focus indicators or making an interaction mouse-only.
- Adding ARIA that conflicts with native semantics.

## CSS and JavaScript integration

Use CSS classes for presentation and JavaScript event listeners for behavior. Keep the document useful if CSS or JavaScript fails. For dynamic content, prefer `textContent` for untrusted strings and update both visual and semantic state.

```html
<button type="button" class="details-toggle" aria-expanded="false" aria-controls="more-info">
  Show learning details
</button>
<div id="more-info" hidden>
  <p>The extra information is available on request.</p>
</div>
<script src="/scripts/details.js" defer></script>
```

## Testing checklist

1. Confirm the document has a doctype and a meaningful `lang` value.
2. Validate nesting, attributes, IDs, and relationships.
3. Test with CSS disabled and with keyboard navigation only.
4. Check zoom, small screens, long content, and high-contrast settings.
5. Inspect the accessibility tree and verify names, roles, and states.
6. Validate and authorize user input on the server when forms are involved.
